# 搬运任务与持续监听实战

TG Migrator 提供两种互补的搬运工作流：
1. **单次与批量搬运任务（Tasks）**：向 Bot 发送消息链接或消息区间，执行一次性历史搬运。
2. **持续监听路由（Watch Routes）**：将源频道/群组/子话题与一个或多个目的地长期绑定，实现 7×24 小时实时同步与历史回溯。

---

## 1. 单次与批量搬运任务

需要将特定消息、整组相册（Album）或指定消息区间搬运至目的地时，可直接将链接发送至 Bot 私聊窗口。

### 支持的链接与区间格式

| 搬运场景 | 发送至 Bot 的输入格式示例 |
| :--- | :--- |
| **单条消息 / 整组相册** | `https://t.me/c/123456789/42`<br>`https://t.me/public_channel/42` |
| **子 Topic 内的单条消息** | `https://t.me/c/123456789/15/42` *（自动识别子话题 `15` 的第 `42` 号消息）* |
| **消息 ID 区间（连字符语法）** | `https://t.me/c/123456789/100-500`<br>`https://t.me/c/123456789/15/100-500` *（仅扫描子话题 `15` 内 100~500 号消息）* |
| **消息 ID 区间（首尾双链接）** | `https://t.me/c/123456789/100 https://t.me/c/123456789/500` |
| **私密群邀请链接** | `https://t.me/+AbCdEfGhIjKlMnOp` *（需读取号已加入该群组）* |

### 选择目的地并启动任务

发送链接后：
1. Bot 会返回一张**目的地多选卡片**（例如 `☑️ #1 归档群_t128`、`⬜ #2 nas_video`）。
2. 点击按钮可勾选或取消目标目的地（支持**一源多投**，例如同时投递至 Telegram 群组与 WebDAV 存储）。
3. 点击 **`🚀 开始`**，扫描器即将匹配的消息入队并交由后台 Worker 并发执行。

> [!TIP] 相册自动聚合与全局幂等去重
> - **相册自动完整搬运**：即使仅发送多图相册中某一张图片的链接，系统也会自动向前后探测相同的 `grouped_id`，将整组相册合并为单个任务整组投递，避免拆散刷屏。
> - **全局幂等去重**：所有媒体文件按 Telegram 全局唯一 `doc_id / photo_id` 计算去重键。重复扫描重叠区间时，已完成投递的内容会自动跳过。

## 2. 持续监听路由（`/routes`）

如需长期跟踪某个源群组/频道（或其中某个特定子 Topic）并实时同步新消息，可创建 **监听路由（Route）**。

### 新建监听路由步骤

1. 打开 **`🔁 路由`** → 点击 **`➕ 新建路由`**（或发送 `/add_route`）。
2. 按 4 步交互向导完成配置：
   - **路由名称**：如 `design_channel_sync`
   - **来源（Source）**：
     - 直接发送一条源群组/频道的消息链接；
     - **锁定源子 Topic**：若发送的是包含子话题 ID 的消息链接（如 `https://t.me/c/123456/15/99`），该路由会自动锁定**仅监听子话题 `15`**，忽略该群组内其他话题的消息；
     - 也可直接输入 `@用户名` 或 `-100<群ID> [话题ID]`。
   - **目的地编号**：输入一个或多个目的地 ID，以英文逗号分隔（如 `1, 2`）。
   - **开启实时监听（`y/n`）**：输入 `y` 立即启用监听。

### 实时事件 + 水位线轮询「双保险机制」

为防止网络波动或容器重启期间遗漏消息，监听引擎采用双通道架构：
1. **Telethon 实时事件流**：源端发布新消息瞬间实时捕获（针对相册消息自动开启 2.5 秒聚合窗口，成组后统一入队）。
2. **`last_seen_msg_id` 水位线周期轮询**：每隔 `watch.poll_interval_seconds`（默认 `300` 秒），自动拉取源会话中大于数据库水位线 ID 的增量消息。即使宿主机断网或停机维护，恢复连接后也会自动从断点补齐停机期间产生的所有消息。

### 在路由上回溯历史消息（`📜 扫描历史`）

进入 **`🔁 路由`** → 选择目标路由 → 点击 **`📜 扫描历史`**：
- **`全部历史（从 1 开始）`**：从第 1 条消息起完整扫描该源会话（或源子话题）的全部存量历史消息。
- **`指定范围`**：输入 `起始ID - 结束ID`（如 `1 - 1000` 或首尾两条消息链接）执行分段回溯。
- **`⏩ 立即补齐`**：立即触发一次水位线增量轮询。

## 3. 关键词与正则内容过滤（`/filters`）

单次任务与持续监听路由均支持通过过滤规则自动拦截推广信息、外部链接或特定关键词。

- **打开过滤面板**：发送 `/filters`（或依次点击 **`⚙️ 设置` → `🧹 过滤规则`**）。
- **新增关键词过滤规则**：
  ```text
  /filter_add keyword 广告合作
  ```
- **新增正则表达式过滤规则**（例如拦截含群组邀请链接的消息）：
  ```text
  /filter_add regex https?://t\.me/(\+|joinchat/)\S+
  ```
- **删除过滤规则**：
  ```text
  /filter_del 1
  ```

## 4. 单路由独立参数覆盖（`/route_set`）

每条监听路由均支持设置独立的运行时参数覆盖，优先级高于全局设置。例如在全局保留消息文字说明（Caption）的前提下，仅在某一条特定路由上剥离说明文字或仅搬运媒体：

```text
# 仅在 1 号路由上剥离媒体说明文字（只发纯图/纯视频）
/route_set 1 transfer.drop_caption true

# 仅在 1 号路由上忽略纯文本消息
/route_set 1 transfer.include.text false

# 清除 1 号路由的覆盖项，恢复跟随全局设置
/route_set 1 transfer.drop_caption -
```

---

## 5. 队列控制与故障恢复

- **查看实时队列与磁盘空间**：发送 `/status`（或点击主菜单 **`📊 状态`**）。
- **暂停与恢复队列**：发送 `/pause`（等待当前正在传输的文件完成后安全暂停）与 `/resume`。
- **重试失败作业**：发送 `/retry`（重试全部失败项）或 `/retry 5`（仅重试任务 `#5` 中的失败项）。
- **取消正在执行的任务**：发送 `/cancel_task 5`（或在 **`📋 任务`** 详情页点击 **`✖️ 取消任务`**）。
- **目的地到达率校验**：发送 `/verify`，系统将抽检已投递至 Telegram 目的地的历史消息是否仍然完好存在。
