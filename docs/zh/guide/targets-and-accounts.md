# 账号登录与目的地绑定（含子 Topic 详解）

本手册介绍如何登录个人读取账号（`/login`）、绑定 Telegram 群组/频道与**指定子 Topic（子话题）**、配置本地 NAS 目录与 WebDAV 归档目的地，以及配置超大文件（> 2GB）自动兜底策略。

---

## 1. 登录个人读取账号（`/login`）

受 Telegram 官方平台机制限制，Bot 账号无法通过邀请链接加入群组，也无法直接拉取非自身管理频道的历史消息。通过登录个人 Telegram 账号作为 **读取账号（Reader）**，系统即可读取该账号已加入的任意群组、频道或子话题。

### 标准登录流程

1. 在与 Bot 的私聊界面点击 **`🔑 账号`**（或发送 `/login`）。
2. 点击 **`📱 开始登录`**，发送带国际区号的手机号（例如 `+8613800138000` 或 `+12025550123`）。
3. Telegram 官方客户端将收到 5 位数字登录验证码。
   > [!CAUTION] 必须使用面板内置数字键盘输入验证码
   > 切勿在 Telegram 聊天输入框中直接以纯文本发送验证码。一旦验证码以普通消息形式发送至 Telegram 会话，Telegram 风控系统会立即判定验证码泄露并使其失效。**请务必通过点击 Bot 消息下方的内联数字按钮输入**，输入完毕后点击 `✔️` 提交。
4. **两步验证密码（2FA）验证（如已启用）**：
   直接在聊天窗口发送两步验证密码（Bot 读取后会立即自动删除该条密码消息）。
   > [!TIP] 包含特殊字符（`_`、`*`、`~`、`||`）的密码处理
   > Telegram 客户端会自动将成对的 `_`（斜体）、`*`（粗体）、`~`（删除线）、`||`（剧透）解析为富文本格式并剥离原始符号。
   > 若密码中包含上述符号，请使用英文单反引号将其包裹为行内代码发送：
   > ```text
   > `my_s3cret_p*ssw0rd`
   > ```
   > 若未加反引号导致符号被客户端解析，系统会自动检测到富文本实体、拒绝受损输入，并提示使用反引号重新发送。

## 2. 绑定 Telegram 目的地（群组、频道与子 Topic）

TG Migrator 支持将消息投递至以下 Telegram 目的地：
- 普通群组与超级群组
- 广播频道（Channel）
- 开启了话题（Forum Topics）群组中的 **指定子 Topic**

### 场景 A：绑定普通群组或主话题（General）

1. 将 Bot 添加至目标群组，并授予发送消息与媒体权限。
2. 在群组内（或默认的 `General` 主话题内）发送 `/bind`。
3. Bot 会自动清理 `/bind` 指令消息，并在私聊窗口返回绑定结果：
   `🎯 已绑定为目的地 #1 归档群`

### 场景 B：绑定群组内的「指定子 Topic」

`/bind` 指令遵循 **「在哪个话题上下文中发送，即绑定哪个话题」** 的规则。若直接在 `# General` 主话题发送 `/bind`，则只会绑定主话题。绑定特定子 Topic 的标准步骤如下：

1. 打开开启了 Topics 功能的目标群组，**先点击进入需要作为目的地的具体子 Topic（子话题）聊天视图**（切勿停留在 `# General` 主话题）。
2. 在该子 Topic 的消息输入框中发送：
   ```text
   /bind
   ```
3. 系统会自动提取该消息所属子话题的 `topic_id`，并注册独立绑定该子话题的目的地：
   `🎯 已绑定为目的地 #2 归档群_t128 (归档群 · Topic 128)`

::: tip 同一群组内绑定多个子 Topic
在同一个群组的不同子话题中分别发送 `/bind`，系统会创建多个相互独立的目的地（例如 `归档群_t10`、`归档群_t25`）。借此可将不同源频道的内容分流归档至同一群组的不同子 Topic 中。
:::

### 场景 C：在私聊窗口通过 `/add_tg` 手动指定子 Topic ID

除在子话题内发送 `/bind` 外，也可在与 Bot 的私聊窗口中通过命令直接绑定子 Topic：

1. 在目标子话题内任意一条消息上右键（或长按），选择 **复制消息链接（Copy Message Link）**。
2. 子话题消息链接的标准格式如下：
   `https://t.me/c/1234567890/128/456`
   - `1234567890` → 对应群组 ID `-1001234567890`
   - `128` → **中间段数字即为该子话题的 Topic ID**
   - `456` → 消息 ID
3. 在与 Bot 的私聊窗口发送：
   ```text
   /add_tg -1001234567890 128
   ```
   即可将该子话题注册为目的地。

### 场景 D：绑定广播频道或以「匿名管理员」身份绑定

在广播频道（或启用群组匿名管理员身份）中发言时，Telegram 消息不包含个人 `sender_id`。此时需使用一次性绑定码完成鉴权：

1. 先在**与 Bot 的私聊窗口**发送 `/bind`；
2. Bot 会生成一个 10 分钟内有效的一次性绑定指令，例如：
   `• 频道或匿名管理员：在其中发送 /bind 839201（10 分钟内有效）`
3. 将 `/bind 839201` 复制并发送至目标频道或群组内即可完成绑定。

## 3. 绑定本地 NAS 目录（`/add_local`）

本地目录目的地会将媒体文件及可选的元数据伴生文件保存在容器内 `/app/archive`（对应宿主机 `./archive` 或挂载的外部 NAS 路径）下。

1. 进入 **`🎯 目的地`** → 点击 **`➕ 本地`**（或发送 `/add_local`）。
2. 输入目的地名称（例如 `nas_video`）。
3. 输入 `ARCHIVE_ROOT` 下的相对子目录路径（如 `telegram/videos`），或发送 `-` 直接存放在 `/app/archive` 根目录。
4. 归档目录结构默认按源会话归类：
   `<ARCHIVE_ROOT>/<子目录>/<源频道名称>/<YYYY-MM>/<消息ID>_<原始文件名>`

### 元数据伴生文件（`archive.sidecar_format`）
每条归档消息旁可自动生成记录完整正文、原始时间戳、发送者 ID 与源链接的伴生文件：
- `json`（默认）：结构化 JSON 元数据
- `md`：适配 Obsidian / Logseq 检索的 `.md` 笔记格式
- `both`：同时生成 `.json` 与 `.md`
- `none`：仅保存媒体文件本身

可通过 `/set archive.sidecar_format md` 在线切换格式。

## 4. 绑定 WebDAV 服务器（`/add_webdav`）

WebDAV 目的地兼容 **OpenList**、**Nextcloud**、**ownCloud**、**Synology WebDAV Server** 以及 **rclone serve webdav**。

1. 进入 **`🎯 目的地`** → 点击 **`➕ WebDAV`**（或发送 `/add_webdav`）。
2. 按向导提示依次输入配置参数：
   - **目的地名称**：如 `openlist_backup`
   - **WebDAV 地址**：支持公网 `https://...` 以及内网/容器网络 `http://...`（如 `http://openlist:5244/dav`）。
     > [!NOTE] 内网地址自动绕过代理（LAN Bypass）
     > 即使在 `.env` 中配置了全局 `PROXY_URL`，指向私有内网网段（`127.0.0.1`、`192.168.x.x`、`10.x.x.x`、`100.64.x.x` Tailscale/CGNAT）以及单标签容器服务名（如 `http://openlist:5244`）的请求均会**自动直连，不经过代理服务器**。
   - **用户名**：WebDAV 账号用户名（匿名访问填 `-`）。
   - **密码**：WebDAV 账号密码（落库前自动使用 Fernet AES-128-CBC + HMAC-SHA256 加密存储；若密码包含 `_`、`*`、`~` 等符号，请使用反引号 `` `密码` `` 包裹发送）。
   - **服务器子目录**：如 `OneDrive/TG归档`（远端目录不存在时会自动通过 `MKCOL` 逐级创建）。

### 自动模式（`auto`）、落盘模式（`spool`）与零磁盘流式直传（`stream`）
通过 `archive.webdav_mode` 参数控制上传策略：
- **`auto`（默认）**：可用磁盘空间充足时先落盘再上传，磁盘空间紧张时自动切换为流式直传。
- **`spool`（落盘缓冲上传）**：先下载至临时目录 `downloads/active` 再上传至 WebDAV，支持断点重试，适合网络波动环境。
- **`stream`（零磁盘流式直传）**：从 Telegram MTProto 边拉取分片边通过 HTTP PUT 流式写入 WebDAV，**全程零本地磁盘占用**，适合小容量磁盘 VPS（可执行 `/set archive.webdav_mode stream` 启用）。

## 5. 超大文件（> 2GB / 4GB）自动兜底策略

Telegram 普通账号与 Bot 的单文件上传上限为 **2,000 MiB（约 2GB）**，Telegram Premium 会员账号上限为 **4,000 MiB（约 4GB）**。针对超过上传上限的大文件，系统提供两种自动兜底机制：

1. **配置超限备用归档目的地（推荐）**：
   进入 **`🎯 目的地`** → 选择对应的 Telegram 目的地 → 点击 **`🗄 设置超限备用`** → 选择一个本地目录或 WebDAV 目的地。配置后，2GB 以内的文件正常发往 Telegram 群组，超出上限的大文件会自动转存至指定的本地 NAS 或 WebDAV 目的地。
2. **启用 Premium 读取号兜底上传**：
   若已登录的读取账号具备 Telegram Premium 会员资格，且在目标 Telegram 群组/频道中拥有发言权限，可执行：
   ```text
   /set transfer.allow_premium_user_fallback true
   ```
   当遇到 2GB ~ 4GB 之间的文件时，系统会自动切换为该 Premium 读取账号完成上传。
